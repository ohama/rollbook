<task type="auto">
  <name>Task 3: Deploy to Vercel and configure environment variables</name>
  <files>N/A (Vercel remote configuration)</files>
  <action>
Deploy to Vercel using CLI (faster and more reliable than GitHub integration for first deploy).

Prerequisites from user_setup:
- User has Vercel account
- User has authorized Vercel to access the repository (if using GitHub integration)

Option A: Deploy via Vercel CLI (RECOMMENDED)
```bash
# Install Vercel CLI globally if not installed
npm install -g vercel

# Login to Vercel
vercel login
# Opens browser for GitHub OAuth

# Deploy to production
vercel --prod
# Prompts:
# - Link to existing project? N (first deploy)
# - Project name: rollbook
# - Deploy location: (current directory)
# - Override settings? N (use defaults from package.json)

# Set environment variables (REQUIRED before site works)
vercel env add VITE_SUPABASE_URL production
# Paste value from Supabase Dashboard → Project Settings → API → Project URL

vercel env add VITE_SUPABASE_ANON_KEY production
# Paste value from Supabase Dashboard → Project Settings → API → anon public key

# Redeploy to apply environment variables
vercel --prod
```

Option B: Deploy via Vercel Dashboard (if CLI fails)
1. Vercel Dashboard → Add New Project
2. Import Git Repository → Select rollbook repo
3. Configure Project:
   - Framework Preset: Vite
   - Build Command: npm run build
   - Output Directory: dist
4. Environment Variables:
   - VITE_SUPABASE_URL = (paste from Supabase)
   - VITE_SUPABASE_ANON_KEY = (paste from Supabase)
   - Select: Production (check only Production, not Preview/Development yet)
5. Deploy

After deployment:
- Copy production URL from output (e.g., https://rollbook-xxx.vercel.app)
- Store in STATE.md for future reference

RESEARCH INSIGHT: Environment variables must be set BEFORE deployment or build will use undefined values. If first deploy succeeds but shows undefined URL errors, set env vars and redeploy.
