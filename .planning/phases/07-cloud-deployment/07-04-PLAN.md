3. **핵심 개념 (Core Concepts)**
   Explain 6 key concepts with beginner-friendly language:

   a. **데이터베이스 마이그레이션 (Database Migrations)**
      - 마이그레이션이란: SQL 파일로 스키마 변경 사항 추적
      - 왜 필요한가: 로컬 개발 스키마를 프로덕션에 재현 가능하게 적용
      - supabase db push 동작 원리: 타임스탬프 순서로 마이그레이션 실행
      - Code example: 20260210014517_initial_schema.sql 내용 일부

   b. **환경 변수 (Environment Variables)**
      - 환경 변수란: 코드에 하드코딩하지 않고 외부에서 설정값 주입
      - 왜 필요한가: 로컬/프로덕션 환경 분리, 보안 (비밀키 노출 방지)
      - Vite 환경 변수: VITE_ 접두사, import.meta.env로 접근
      - Code example: import.meta.env.VITE_SUPABASE_URL 사용 패턴

   c. **Vercel 배포 프로세스 (Vercel Deployment)**
      - Vercel이란: 정적 사이트 호스팅 서비스 (Vite 빌드 자동화)
      - 빌드 명령: npm run build → Fable 컴파일 → Vite 번들링
      - 배포 결과: dist/ 폴더 → Vercel CDN에 배포 → 자동 HTTPS 적용
      - Code example: package.json build 스크립트

   d. **RLS 프로덕션 검증 (RLS Production Verification)**
      - 로컬 vs 프로덕션 차이: 로컬은 SQL Editor가 RLS 우회, 프로덕션은 JWT 토큰 필수
      - 검증 방법: 클라이언트 SDK로 테스트 (SQL Editor 사용 금지)
      - 두 사용자 테스트: User A가 User B 데이터 접근 불가 확인
      - Code example: client SDK로 RLS 테스트하는 패턴

   e. **오프라인 큐 충돌 (Offline Queue Conflicts)**
      - 문제: 로컬 Supabase와 프로덕션 Supabase는 JWT 비밀키 다름
      - 증상: 로컬 환경에서 쌓인 오프라인 큐가 프로덕션 배포 후 인증 실패
      - 해결: 배포 전 오프라인 큐 비우기 (localStorage.removeItem('rollbook-offline-queue'))
      - Research insight: 로컬과 클라우드 JWT 비밀키 불일치 문제

   f. **PWA 설치 가능성 (PWA Installability)**
      - PWA 요구사항: HTTPS, manifest, service worker
      - Vercel 자동 지원: 배포 시 자동 HTTPS 적용
      - 모바일 설치: iOS Safari "홈 화면에 추가", Android Chrome "설치"
      - Code reference: vite.config.js의 VitePWA manifest 설정

4. **중요 코드 (Key Code)**
   Display and explain critical code snippets:

   a. **Supabase 클라이언트 생성 (Production)**
   ```typescript
   // src/Supabase/Client.js
   import { createClient } from "@supabase/supabase-js";

   export const supabase = createClient(
     import.meta.env.VITE_SUPABASE_URL,  // 프로덕션: https://xxx.supabase.co
     import.meta.env.VITE_SUPABASE_ANON_KEY,  // 클라우드에서 발급받은 anon key
     {
       auth: {
         persistSession: true,
         autoRefreshToken: true,
         storageKey: "rollbook-auth",
       },
     }
   );
   ```
   설명: 환경 변수를 통해 로컬/프로덕션 자동 전환

   b. **Vercel 환경 변수 설정 (CLI)**
   ```bash
   # Vercel CLI로 환경 변수 추가
   vercel env add VITE_SUPABASE_URL production
   # 값 입력: https://xxx.supabase.co

   vercel env add VITE_SUPABASE_ANON_KEY production
   # 값 입력: eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
   ```
   설명: 환경 변수를 Vercel에 안전하게 저장 (암호화)

   c. **마이그레이션 적용 (Supabase CLI)**
   ```bash
   # 1. Supabase Cloud 프로젝트 연결
   supabase link --project-ref xxx

   # 2. 마이그레이션 푸시
   supabase db push
   # 5개 마이그레이션 파일 순서대로 실행
   ```
   설명: 로컬 migrations/ 폴더 → 클라우드 데이터베이스 자동 적용

5. **배운 점 (Lessons Learned)**
   Document real pitfalls encountered during Phase 7:

   - **Pitfall 1: RLS 정책을 SQL Editor로 테스트**
     - 문제: SQL Editor는 RLS 우회, 프로덕션에서 동작 안 함
     - 해결: 항상 클라이언트 SDK로 테스트 (signInWithPassword → select)

   - **Pitfall 2: 환경 변수 설정 전 배포**
     - 문제: Vercel 첫 배포 후 "Supabase URL is undefined" 에러
     - 해결: 환경 변수 설정 → 재배포 (vercel --prod 다시 실행)

   - **Pitfall 3: 로컬 오프라인 큐 충돌**
     - 문제: 로컬 JWT 토큰으로 쌓인 큐가 프로덕션에서 403 Unauthorized
     - 해결: 배포 전 localStorage.removeItem('rollbook-offline-queue')

   - **Pitfall 4: 마이그레이션 재실행 시 충돌**
     - 문제: 수동으로 스키마 수정 후 supabase db push 실패
     - 해결: 마이그레이션만 사용, 수동 스키마 변경 금지

6. **흔한 실수 (Common Mistakes)**
   - 환경 변수를 .env 파일에만 설정 (Vercel에는 미설정)
   - Service role key를 프론트엔드에 노출 (보안 위험)
   - Public bucket을 RLS 없이 활성화 (사진 URL 노출)
   - 프로덕션 데이터베이스를 SQL Editor로 수동 편집 (마이그레이션 불일치)
