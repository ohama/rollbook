<task type="auto">
  <name>Task 2: Install cloudflared, authenticate, create tunnel, configure routing and DNS</name>
  <files>~/.cloudflared/config.yml</files>
  <action>
    Execute the full cloudflared setup sequence using the domain info from Task 1:

    1. **Install cloudflared** (skip if already installed):
       ```bash
       brew install cloudflared
       cloudflared --version
       ```

    2. **Authenticate with Cloudflare** (opens browser -- user must complete in browser):
       ```bash
       cloudflared tunnel login
       ```
       This creates `~/.cloudflared/cert.pem`. If auth fails (browser interaction needed), pause and let user complete the browser authentication, then retry.

    3. **Create the tunnel**:
       ```bash
       cloudflared tunnel create rollbook
       ```
       Capture the TUNNEL_ID from output. The credentials file `~/.cloudflared/<TUNNEL_ID>.json` is created automatically.

    4. **Write config.yml** with ABSOLUTE paths (critical for launchd -- see research pitfall #1):
       ```yaml
       tunnel: rollbook
       credentials-file: /Users/<actual-username>/.cloudflared/<TUNNEL_ID>.json

       ingress:
         - hostname: <frontend-subdomain>
           service: http://localhost:4173
         - hostname: <api-subdomain>
           service: http://localhost:54321
         - service: http_status:404
       ```
       Use the actual username from `whoami` and the actual TUNNEL_ID from step 3.
       NEVER use `~` in paths -- launchd does not expand tilde.
       NEVER include Supabase Studio (port 54323) in ingress rules (security risk per research).

    5. **Validate config**:
       ```bash
       cloudflared tunnel ingress validate
       ```

    6. **Create DNS CNAME records**:
       ```bash
       cloudflared tunnel route dns rollbook <frontend-subdomain>
       cloudflared tunnel route dns rollbook <api-subdomain>
       ```

    7. **Test tunnel** (brief run to verify connectivity):
       ```bash
       cloudflared tunnel run rollbook
       ```
       Run for ~10 seconds to confirm "Connection registered" messages, then Ctrl+C.

    IMPORTANT: If `cloudflared tunnel login` triggers a browser window, this is expected. The user must complete authentication in the browser. If running in a headless context, the CLI will print a URL the user must visit.
  </action>
  <verify>
    - `cloudflared --version` shows installed version
    - `cloudflared tunnel list` shows "rollbook" tunnel
    - `cloudflared tunnel ingress validate` returns "ok"
    - `ls ~/.cloudflared/config.yml` exists
    - `ls ~/.cloudflared/*.json` shows credentials file
    - DNS records visible: `cloudflared tunnel route dns rollbook <frontend-subdomain>` (already exists message)
  </verify>
