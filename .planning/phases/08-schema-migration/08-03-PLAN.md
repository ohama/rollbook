Update replayOperation function to remove onConflict and support soft delete.

Changes to src/offline/Sync.fs:

1. **Update CreateWorkout case** (remove onConflict):
```fsharp
match operation.operationType with
| "CreateWorkout" ->
    // No longer use onConflict (no unique constraint)
    let! response =
        client
            ?from("workouts")
            ?insert(
                createObj [
                    "user_id" ==> operation.userId
                    "workout_date" ==> operation.workoutDate
                    "record_type" ==> operation.recordType  // Use from queue
                    "text_content" ==> operation.textContent
                    "photo_url" ==> operation.photoUrl
                ]
            )

    let error = response?error

    if isNull error then
        // Success: remove from queue
        let! _ = dequeue (defaultArg operation.id 0)
        return SyncResult.Success (defaultArg operation.id 0)
    else
        // Failure: increment retry
        let! _ = incrementRetry (defaultArg operation.id 0)
        return SyncResult.Error (defaultArg operation.id 0, error?message)
```

2. **Update DeleteWorkout case** (soft delete):
```fsharp
| "DeleteWorkout" ->
    // Soft delete by setting deleted_at
    // NOTE: In v1, we deleted by (user_id, date). In v2, we need recordId.
    // For now, keep old behavior (delete all records for user+date)
    // Phase 10 will update to delete by recordId
    let! response =
        client
            ?from("workouts")
            ?update(createObj ["deleted_at" ==> System.DateTime.UtcNow.ToString("o")])
            ?eq("user_id", operation.userId)
            ?eq("workout_date", operation.workoutDate)
            ?is("deleted_at", null)  // Only soft-delete non-deleted records

    let error = response?error

    if isNull error then
        let! _ = dequeue (defaultArg operation.id 0)
        return SyncResult.Success (defaultArg operation.id 0)
    else
        let! _ = incrementRetry (defaultArg operation.id 0)
        return SyncResult.Error (defaultArg operation.id 0, error?message)

| _ ->
    // Unknown operation type
    return SyncResult.Error (defaultArg operation.id 0, "Unknown operation type")
```

3. Add logging for debugging:
```fsharp
// At start of replayOperation
printfn "Replaying operation: %s (id=%A)" operation.operationType operation.id
```

IMPORTANT: The DeleteWorkout logic is a transitional implementation. It soft-deletes all records for a user+date (preserving v1 behavior). Phase 10 will update to delete by recordId when UI supports individual record deletion.
