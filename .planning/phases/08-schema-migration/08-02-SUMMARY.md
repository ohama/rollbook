# Phase 08 Plan 02: Frontend Types and API Summary

**F# types and API updated for v2.0 schema with soft-delete, simple insert, and IndexedDB v2**

## Accomplishments
- Updated WorkoutRecord type with 9 fields (id, record_type, text_content, photo_url, updated_at, deleted_at)
- Updated QueuedOperation with recordId, recordType, textContent, photoUrl fields
- Removed onConflict from Workouts.fs (simple insert instead of upsert)
- Implemented soft-delete in deleteWorkout (UPDATE deleted_at)
- Added getWorkoutsForDate and deleteWorkoutById for Phase 10+
- Bumped IndexedDB to v2 with upgrade handler that clears v1 queue
- All queries filter deleted_at IS NULL

## Decisions Made

**F# source is truth (not JS)**
- Discovery: This is a Fable (F#→JS) project. Initial executor modified JS files directly.
- Fix: Modified F# source files and let Fable regenerate JS via `npm run build`
- Rule: Always edit .fs files, never .js compiled output

**Keep upsertWorkout for backward compat**
- Dashboard.fs calls upsertWorkout — rename would break UI
- Added createWorkout as alias for Phase 10+ usage

**emitJsExpr for IndexedDB upgrade**
- Fable's curried functions don't map to multi-arg JS callbacks
- Used emitJsExpr to write the upgrade(db, oldVersion, newVersion, tx) handler directly

## Deviations from Plan

**Major: F# source files modified instead of JS**
- Plan referenced JS files but project uses Fable (F#→JS compiler)
- F# source is the truth; JS is compiled output
- All changes made in .fs files, Fable regenerates .js

## Issues Encountered

**Executor modified wrong files**
- Initial executor subagent modified .js files directly
- Discovery: `npm run dev` runs Fable watch + Vite, overwriting JS on every F# change
- Resolution: Redo all changes in F# source files
