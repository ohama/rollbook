Create migration SQL file following the blue-green table rename pattern from RESEARCH.md Pattern 1.

Structure (in single transaction):
1. BEGIN transaction
2. Rename: workouts → workouts_v1_backup
3. Create new workouts table with:
   - id BIGSERIAL PRIMARY KEY
   - user_id UUID (FK to auth.users, cascade delete)
   - workout_date DATE NOT NULL
   - record_type TEXT DEFAULT 'workout' CHECK (IN 'workout', 'text', 'photo')
   - text_content TEXT
   - photo_url TEXT
   - created_at TIMESTAMPTZ DEFAULT NOW()
   - updated_at TIMESTAMPTZ
   - deleted_at TIMESTAMPTZ
4. Copy data: INSERT INTO workouts SELECT from workouts_v1_backup (all as record_type='workout')
5. Verification block (DO $$) - compare row counts, RAISE EXCEPTION if mismatch
6. Create indexes:
   - idx_workouts_user_date ON (user_id, workout_date)
   - idx_workouts_date ON (workout_date)
   - idx_workouts_deleted ON (deleted_at) WHERE deleted_at IS NULL
7. Enable RLS
8. Create policies:
   - SELECT: authenticated users can view all non-deleted records
   - INSERT: users can create own records
   - UPDATE: users can update own non-deleted records (for soft delete)
9. Add table comment documenting v2.0 schema change
10. COMMIT

IMPORTANT: Use exact SQL structure from RESEARCH.md Pattern 1. Do NOT skip verification step.

Also create rollback script: rollback_migration.sql (DROP new table, RENAME backup back).
