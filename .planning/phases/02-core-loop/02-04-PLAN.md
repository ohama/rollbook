  <how-to-verify>
**Prerequisites:**
1. Ensure Supabase is running: `supabase status`
2. Start dev server: `npm run dev`
3. Open browser to http://localhost:5173

**Test Flow:**

**Test 1: One-tap toggle (WORK-01)**
1. Login with existing test account
2. Dashboard shows toggle button with ⭕ emoji and "오늘 운동했다" text
3. Click button once
4. Button should:
   - Show loading state briefly (disabled, grayed)
   - Change to 💪 emoji
   - Change text to "운동 완료!"
   - Change color to green
5. Click button again
6. Button should:
   - Show loading state briefly
   - Change back to ⭕ emoji
   - Change text to "오늘 운동했다"
   - Change color to indigo
7. ✅ PASS if toggle works both directions without errors

**Test 2: Persistence (WORK-01)**
1. Click "오늘 운동했다" (if not already logged)
2. Verify button shows "운동 완료!" with 💪
3. Refresh browser (F5)
4. After page reload, button should still show "운동 완료!" with 💪
5. ✅ PASS if state persists across refresh

**Test 3: Database uniqueness constraint (implicit requirement)**
1. Open browser console (F12)
2. Click toggle button rapidly 5-10 times
3. Wait for all requests to complete
4. Check Supabase logs or query database:
   ```sql
   SELECT COUNT(*) FROM workouts WHERE user_id = '<your-user-id>' AND workout_date = CURRENT_DATE;
   ```
5. ✅ PASS if count is 1 (no duplicates despite rapid clicks)

**Test 4: RLS Security (implicit requirement)**
1. Open Supabase dashboard: `supabase studio`
2. Navigate to Table Editor → workouts
3. Should see your own workout records
4. Create second test account (different browser/incognito)
5. Login with second account
6. Toggle workout for second user
7. Verify in Supabase dashboard that each user only sees their own records
8. ✅ PASS if RLS isolates users' data

**Test 5: Error handling**
1. Stop Supabase: `supabase stop`
2. Click toggle button in running app
3. Should show error message: "저장 실패. 다시 시도해주세요."
4. Restart Supabase: `supabase start`
5. Click toggle again
6. ✅ PASS if error shows when offline and recovers when online

**Test 6: Mobile responsiveness (TECH-01 partial)**
1. Open browser dev tools (F12)
2. Toggle device toolbar (mobile view)
3. Select iPhone 12 or similar
4. Verify:
   - Button is large enough to tap easily (min 44x44px)
   - Text is readable
   - Layout doesn't break
   - No horizontal scroll
7. ✅ PASS if usable on mobile screen

**Requirements Coverage:**
- WORK-01: One-tap toggle → Test 1, 2
- WORK-02: Edit records → Deferred to Phase 3 (toggle handles today only)
- WORK-03: Delete records → Test 1 (toggle includes delete)
- WORK-05: Log any date → Deferred to Phase 3 (calendar picker)
- TECH-01: Mobile responsive → Test 6 (partial, full test in Phase 3)

**Note:** WORK-02 (edit) and WORK-05 (any date) bindings exist from Plan 02 but UI not built yet. This is intentional - Phase 2 focuses on core one-tap flow for TODAY only. Calendar/editing UI comes in Phase 3.
