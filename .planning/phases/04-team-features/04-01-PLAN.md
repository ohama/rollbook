**Part 1: SECURITY DEFINER function for team monthly stats**

- Uses SECURITY DEFINER (bypasses workouts table RLS)
- Sets `search_path = public, pg_catalog` (security best practice)
- Returns TABLE (user_id UUID, display_name TEXT, workout_count BIGINT)
- Uses LEFT JOIN from profiles to workouts (ensures users with 0 workouts appear)
- Filters by EXTRACT(YEAR/MONTH FROM workout_date)

**Part 2: Profiles RLS policy for team roster viewing**

Add new policy "Authenticated users can view team roster" on profiles table:
- FOR SELECT
- TO authenticated
- USING (true) - all authenticated users can see all profiles

This policy works WITH existing "Users can view own profile" policy (Postgres OR's them).

**Part 3: Optional performance index**

Create index on workouts for (year, month) extraction:
- idx_workouts_year_month on EXTRACT(YEAR FROM workout_date), EXTRACT(MONTH FROM workout_date)

**Code pattern from research:**
```sql
CREATE OR REPLACE FUNCTION public.get_team_monthly_stats(
    target_year INT,
    target_month INT
)
RETURNS TABLE (
    user_id UUID,
    display_name TEXT,
    workout_count BIGINT
)
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = public, pg_catalog
AS $$
BEGIN
    RETURN QUERY
    SELECT
        p.id AS user_id,
        COALESCE(p.display_name, 'Anonymous') AS display_name,
        COUNT(w.workout_date)::BIGINT AS workout_count
    FROM public.profiles p
    LEFT JOIN public.workouts w ON p.id = w.user_id
        AND EXTRACT(YEAR FROM w.workout_date) = target_year
        AND EXTRACT(MONTH FROM w.workout_date) = target_month
    GROUP BY p.id, p.display_name
    ORDER BY workout_count DESC, p.display_name NULLS LAST;
END;
$$;
```
