<task type="auto">
  <name>Task 1: Install bundle analyzer and configure optimization</name>
  <files>
    package.json
    vite.config.ts
  </files>
  <action>
    1. Install rollup-plugin-visualizer:
    ```bash
    npm install -D rollup-plugin-visualizer
    ```

    2. Update vite.config.ts to add visualizer and optimization:
    ```typescript
    import { defineConfig } from 'vite';
    import tailwindcss from '@tailwindcss/vite';
    import { VitePWA } from 'vite-plugin-pwa';
    import { visualizer } from 'rollup-plugin-visualizer';

    export default defineConfig({
      plugins: [
        tailwindcss(),
        VitePWA({
          // ... existing PWA config
        }),
        visualizer({
          filename: 'dist/stats.html',
          open: false,  // Don't auto-open
          gzipSize: true,
          brotliSize: true,
        })
      ],
      server: {
        port: 3000,
      },
      build: {
        rollupOptions: {
          output: {
            manualChunks: {
              // Vendor chunk for React
              'vendor-react': ['react', 'react-dom'],
              // Supabase client in its own chunk
              'vendor-supabase': ['@supabase/supabase-js'],
              // IDB for offline (small, but separate)
              'vendor-offline': ['idb'],
            }
          }
        },
        // Warn if any chunk exceeds 500KB
        chunkSizeWarningLimit: 500,
        // Enable minification
        minify: 'terser',
        terserOptions: {
          compress: {
            drop_console: true,  // Remove console.log in production
          }
        }
      }
    });
    ```

    Key decisions:
    - Separate vendor chunks to enable better caching (React rarely changes)
    - Supabase in its own chunk (large library, cached separately)
    - drop_console removes debug logs from production
    - gzipSize/brotliSize in visualizer shows realistic transfer sizes
  </action>
  <verify>
    npm run build completes without errors
    dist/stats.html is generated
    No chunks exceed 500KB warning
  </verify>
  <done>Bundle analyzer installed and optimization configured</done>
</task>

    2. Check bundle sizes:
    ```bash
    # List all chunks with sizes
    ls -lah dist/assets/*.js

    # Get total JS size
    du -ch dist/assets/*.js | grep total

    # Check gzip sizes (more realistic for transfer)
    for f in dist/assets/*.js; do
      gzip -c "$f" | wc -c | xargs -I {} echo "$f: {} bytes gzipped"
    done
    ```

<task type="auto">
  <name>Task 3: Perform Supabase Security Advisor audit</name>
  <files>None (audit only)</files>
  <action>
    Run Supabase Security Advisor checks via CLI:

    1. If local Supabase running:
    ```bash
    # Check for security issues
    supabase db lint

    # Specifically check RLS
    supabase db lint --level error
    ```

    2. Manual security checklist (document in SUMMARY):

    **RLS Verification:**
    - [ ] All tables have RLS enabled
    - [ ] profiles: Users can view all (team), only admin can delete
    - [ ] workouts: Users can CRUD own workouts, team can view
    - [ ] user_roles: Users can view own roles, no write access
    - [ ] storage.objects (workout-photos): Users can only access own folder

    **Query patterns:**
    - [ ] All RLS policies use (SELECT auth.uid()) wrapper for performance
    - [ ] Indexes exist on RLS-checked columns (user_id)

    **Auth security:**
    - [ ] Email confirmation enabled
    - [ ] Password requirements enforced (Supabase default: 6+ chars)
    - [ ] JWT expiry reasonable (default: 1 hour)

    **API security:**
    - [ ] Anon key only allows authenticated operations via RLS
    - [ ] Service role key NOT exposed in client code
    - [ ] No sensitive data in JWT claims

    3. Check for common vulnerabilities:
    ```sql
    -- Run in Supabase SQL editor or via psql

    -- Check all tables have RLS
    SELECT schemaname, tablename, rowsecurity
    FROM pg_tables
    WHERE schemaname = 'public';

    -- Check for tables with RLS but no policies
    SELECT t.tablename
    FROM pg_tables t
    LEFT JOIN pg_policies p ON t.tablename = p.tablename
    WHERE t.schemaname = 'public'
      AND t.rowsecurity = true
      AND p.policyname IS NULL;

    -- List all RLS policies
    SELECT tablename, policyname, permissive, roles, cmd, qual
    FROM pg_policies
    WHERE schemaname = 'public';
    ```

    4. Document audit results in SUMMARY with:
    - RLS status for each table
    - Any warnings or issues found
    - Remediation actions taken (if any)
  </action>
  <verify>
    supabase db lint shows no errors (if available)
    All tables have RLS enabled
    No policies return zero rows (empty result = deny all)
    Auth settings verified
  </verify>
  <done>Security audit completed and documented</done>
