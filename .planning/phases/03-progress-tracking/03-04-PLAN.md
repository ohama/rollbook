<task type="checkpoint:human-verify" gate="blocking">
  <what-built>Complete progress tracking feature with calendar view, list view, monthly statistics, and month navigation</what-built>
  <how-to-verify>
**Prerequisites:**
1. Start development server: `npm run dev`
2. Login with existing account that has workout records (from Phase 2)
3. If no workout records exist, create some using "오늘 운동했다" button on Home tab

**Test Sequence:**

**Test 1: Tab Navigation**
- Navigate to "내 기록" tab from Dashboard
- Expected: ProgressView page loads, shows calendar/list toggle buttons
- Expected: MonthlyStats component displays at top

**Test 2: Calendar View (PROG-01)**
- Ensure "캘린더" button is active (calendar view selected)
- Expected: Monthly calendar grid displays with 7 columns (일 월 화 수 목 금 토)
- Expected: Days align correctly (e.g., if month starts on Wednesday, first day appears in 4th column)
- Expected: Days with workouts have green background (bg-green-100)
- Expected: Today's date has indigo border (border-2 border-indigo-600)
- Expected: Current month/year displays at top ("2026년 2월" format)

**Test 3: List View (PROG-02)**
- Click "리스트" button to switch views
- Expected: List view displays with workout records
- Expected: Workouts sorted by date descending (most recent first)
- Expected: Each workout shows 💪 emoji and date (YYYY-MM-DD)
- Expected: If no workouts, shows "운동 기록이 없습니다" message

**Test 4: Monthly Statistics (PROG-03)**
- Check MonthlyStats component (visible in both calendar and list views)
- Expected: Shows current month/year ("2026년 2월")
- Expected: Shows total workout count (e.g., "5")
- Expected: Shows percentage (e.g., "18%" for 5 workouts in 28-day month)
- Expected: Count in indigo color, percentage in green color

**Test 5: Month Navigation**
- Click previous month button (< or 이전)
- Expected: Calendar/list updates to previous month
- Expected: MonthlyStats updates to show previous month's data
- Expected: Month/year display updates (e.g., "2026년 1월")
- Expected: If previous month has no workouts, list shows empty state

- Click next month button (> or 다음)
- Expected: Calendar/list updates to next month
- Expected: MonthlyStats updates to show next month's data
- Expected: Month/year display updates

- Navigate across year boundary (December -> January or January -> December)
- Expected: Year increments/decrements correctly
- Expected: Data loads for new year/month

**Test 6: View Toggle Persistence**
- Switch to list view, then navigate to different month
- Expected: Stays in list view after month navigation
- Switch to calendar view, then navigate to different month
- Expected: Stays in calendar view after month navigation

**Test 7: Data Consistency**
- Compare calendar green days with list view dates
- Expected: Same dates appear in both views (no missing or extra workouts)
- Compare workout count with MonthlyStats display
- Expected: Count matches number of workouts in list/calendar

**Test 8: Mobile Responsiveness**
- Resize browser to mobile width (e.g., 375px)
- Expected: Calendar grid remains readable (7 columns adjust to fit)
- Expected: View toggle buttons stack or wrap appropriately
- Expected: MonthlyStats grid adapts (may stack vertically on very small screens)
- Expected: List view cards remain readable

**Test 9: Edge Cases**
- Navigate to February 2024 (leap year)
- Expected: Calendar shows 29 days
- Navigate to future month with no workouts
- Expected: List shows empty state, stats show 0 workouts, 0%
- Create workout in current month, then navigate away and back
- Expected: New workout appears correctly

**Screenshot Requirements:**
Capture screenshots for:
1. Calendar view with workout indicators (green days)
2. List view with workout records
3. MonthlyStats display showing count and percentage
4. Month navigation (before/after clicking prev/next)
5. View toggle (calendar and list states)

**Issue Reporting:**
If any test fails, document:
- Test number that failed
- Expected vs actual behavior
- Browser console errors (if any)
- Screenshots of failure
