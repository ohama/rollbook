  <action>
Create PostgreSQL migration implementing audit logging infrastructure per research patterns.

**1. Create audit schema and record_version table:**
- audit.record_version with columns: id (bigserial PK), record_id (uuid), old_record_id (uuid), op (varchar 10), ts (timestamptz), user_id (uuid), user_email (text), table_oid (oid), table_schema (name), table_name (name), record (jsonb), old_record (jsonb)
- Use BRIN index on ts for time-series efficiency: `CREATE INDEX record_version_ts ON audit.record_version USING brin(ts);`
- Add B-tree indexes on table_oid, record_id, user_id (with WHERE clause for non-NULL)

**2. Create generic audit.log_change() trigger function:**
- RETURNS trigger, LANGUAGE plpgsql, SECURITY DEFINER
- Capture v_user_id from auth.uid(), v_user_email from auth.users lookup
- For workouts table: generate v_record_id using gen_random_uuid() (workouts.id is BIGSERIAL, not UUID)
- For profiles table: use COALESCE(NEW.id, OLD.id) as v_record_id (profiles.id is UUID)
- For user_roles table: use COALESCE(NEW.user_id, OLD.user_id) as v_record_id
- INSERT into audit.record_version with: record_id, TG_OP, user_id, user_email, TG_RELID, TG_TABLE_SCHEMA, TG_TABLE_NAME
- Use CASE: record = to_jsonb(NEW) for INSERT/UPDATE, old_record = to_jsonb(OLD) for UPDATE/DELETE
- RETURN NEW for INSERT/UPDATE, RETURN OLD for DELETE
- Add pg_trigger_depth() guard: IF pg_trigger_depth() > 1 THEN RETURN NEW/OLD; END IF; (prevent recursion)

**3. Attach triggers to tables:**
- CREATE TRIGGER audit_workouts AFTER INSERT OR UPDATE OR DELETE ON public.workouts FOR EACH ROW EXECUTE FUNCTION audit.log_change();
- CREATE TRIGGER audit_profiles AFTER INSERT OR UPDATE OR DELETE ON public.profiles FOR EACH ROW EXECUTE FUNCTION audit.log_change();
- CREATE TRIGGER audit_user_roles AFTER INSERT OR UPDATE OR DELETE ON public.user_roles FOR EACH ROW EXECUTE FUNCTION audit.log_change();

**4. Add table comments:**
- COMMENT ON TABLE audit.record_version IS 'Audit trail for admin actions. Captures before/after JSONB snapshots.';
- COMMENT ON FUNCTION audit.log_change() IS 'Generic audit trigger. Logs INSERT/UPDATE/DELETE to audit.record_version.';

**Why AFTER triggers:** Capture final state after all triggers execute (research Pattern 2).
**Why JSONB:** Handles schema changes gracefully, queryable, native PostgreSQL type (research Pattern 1).
**Why BRIN on timestamp:** Optimal for time-series audit queries, much smaller than B-tree (research Pitfall 6).
**Why pg_trigger_depth() guard:** Prevent recursion if future triggers on audit table are added (research Pitfall 1).
