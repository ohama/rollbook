    ## 배운 점

    1. Service Worker 캐싱 전략
       - NetworkFirst: API 요청 (최신 데이터 우선)
       - CacheFirst: 정적 파일 (빠른 로딩 우선)
       - NetworkOnly: 인증 요청 (절대 캐시 안 함)

    2. IndexedDB vs localStorage
       - IndexedDB: 구조화된 데이터, Service Worker에서 사용 가능
       - localStorage: 문자열만, Service Worker에서 사용 불가

    3. Background Sync API 지원
       - Chromium 브라우저: 전체 지원
       - Safari/Firefox: 미지원, visibility change 대체

    4. Supabase RLS 성능
       - (SELECT auth.uid()) 래핑으로 쿼리 캐싱
       - 인덱스 생성으로 RLS 체크 최적화

    ## 흔한 실수

    ### 1. Service Worker가 업데이트 안 됨
    - 원인: 브라우저 캐싱
    - 해결: DevTools > Application > Service Workers > Unregister

    ### 2. RLS 활성화 후 데이터 접근 불가
    - 원인: 정책 없이 RLS 활성화 = 전체 거부
    - 해결: RLS 활성화 즉시 정책 생성

    ### 3. 오프라인 큐가 동기화 안 됨
    - 원인: Safari/Firefox에서 Background Sync 미지원
    - 해결: visibility change 또는 online 이벤트 대체

    ### 4. 번들 크기 초과
    - 원인: 사용하지 않는 코드 포함
    - 해결: rollup-plugin-visualizer로 분석, 불필요한 import 제거
