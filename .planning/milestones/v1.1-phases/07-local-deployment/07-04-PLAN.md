<task type="auto">
  <name>Task 1: Start all services and verify infrastructure</name>
  <files></files>
  <action>
    1. **Ensure Supabase is running** (may already be running from development):
       ```bash
       npx supabase status
       ```
       If not running, start it:
       ```bash
       npx supabase start
       ```

    2. **Ensure production build is current**:
       ```bash
       npm run build
       ```

    3. **Start all services via management script**:
       ```bash
       ./scripts/rollbook-services.sh start
       ```

    4. **Wait for services to become healthy** (up to 60 seconds):
       ```bash
       # Wait for Supabase API
       for i in $(seq 1 12); do
         curl -sf http://localhost:54321/rest/v1/ -H "apikey: dummy" > /dev/null 2>&1 && break
         echo "Waiting for Supabase... ($i)"
         sleep 5
       done

       # Wait for Frontend
       for i in $(seq 1 12); do
         curl -sf http://localhost:4173 > /dev/null 2>&1 && break
         echo "Waiting for Frontend... ($i)"
         sleep 5
       done

       # Check tunnel status
       ./scripts/rollbook-services.sh status
       ```

    5. **Verify tunnel connectivity** (automated checks):
       Read the tunnel domain from 07-01-SUMMARY.md, then:
       ```bash
       # Check frontend via tunnel
       curl -sf -o /dev/null -w "Frontend HTTPS: %{http_code} (redirect: %{redirect_url})\n" https://<frontend-domain>

       # Check API via tunnel
       curl -sf -o /dev/null -w "API HTTPS: %{http_code}\n" https://<api-domain>/rest/v1/ -H "apikey: <anon-key>"
       ```
       Note: Cloudflare Access may intercept and redirect to login. A 302 redirect to cloudflareaccess.com is EXPECTED and means the tunnel is working.
       A direct 200 means Access is not configured (also fine for now).

    6. **Verify MX records preserved** (TUNL-04):
       ```bash
       # Check MX records for the domain
       dig MX <parent-domain> +short
       ```
       Expected output should include Google Workspace MX servers:
       - `aspmx.l.google.com`
       - `alt1.aspmx.l.google.com`
       - etc.
       If MX records are missing, this is a CRITICAL issue -- do NOT proceed.

    7. **Verify HTTPS certificate** (TUNL-03):
       ```bash
       curl -vI https://<frontend-domain> 2>&1 | grep -i "SSL certificate\|subject:\|issuer:"
       ```
       Certificate should be issued by Cloudflare (automatic).

    8. **Check service logs for errors**:
       ```bash
       ./scripts/rollbook-services.sh logs
       ```
       Look for error messages. Common issues:
       - "command not found" = PATH issue in plist
       - "Invalid Host header" = allowedHosts not configured
       - "credentials file not found" = path issue in config.yml
  </action>
  <verify>
    - `./scripts/rollbook-services.sh status` shows all three services RUNNING
    - `curl http://localhost:4173` returns 200
    - `curl http://localhost:54321/rest/v1/` responds (may need apikey)
    - Tunnel domain responds (200 or 302 for Cloudflare Access)
    - `dig MX <domain>` shows Google Workspace MX records
    - No critical errors in service logs
  </verify>
  <done>
    All three services running via launchd. Frontend and API accessible through tunnel. MX records preserved. HTTPS working via Cloudflare.
  </done>
