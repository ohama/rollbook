    1. **개요** (Overview)
       - Phase 7의 목표: Mac Mini + Cloudflare Tunnel 로컬 배포
       - 왜 로컬 배포인가? (데이터 주권, 비용 절감, 완전한 제어)
       - 전체 아키텍처 다이어그램 (Mermaid: 사용자 -> Cloudflare -> Mac Mini)

    2. **아키텍처** (Architecture)
       - Mermaid 다이어그램: 전체 시스템 흐름
         - 인터넷 -> Cloudflare Edge (DNS + HTTPS + Access) -> Tunnel -> Mac Mini
         - Mac Mini 내부: cloudflared -> Vite (4173), Supabase (54321)
       - Mermaid 다이어그램: 서비스 시작 순서
         - Docker Desktop -> Supabase -> Frontend -> Tunnel
       - 각 컴포넌트의 역할 설명

    3. **핵심 개념** (Key Concepts) -- 6 concepts:
       a. **Cloudflare Tunnel**: 아웃바운드 전용 연결, 포트 포워딩 불필요, 자동 HTTPS
       b. **DNS와 CNAME 레코드**: 도메인 -> 터널 라우팅, MX 레코드 보존
       c. **config.yml 인그레스 규칙**: 호스트네임 기반 라우팅, catch-all 규칙
       d. **launchd 서비스 관리**: macOS 네이티브 서비스, RunAtLoad, KeepAlive
       e. **서비스 의존성 처리**: 헬스체크 루프, Docker 대기, Supabase 대기
       f. **프로덕션 빌드 설정**: .env.production, allowedHosts, PWA 캐싱

    4. **중요 코드** (Key Code)
       - config.yml 전체 구조 설명 (각 필드의 의미)
       - plist 파일 구조 설명 (XML 키의 의미, 특히 KeepAlive와 ProgramArguments)
       - vite.config.js 변경사항 (allowedHosts, preview.host, PWA 패턴)
       - .env.production 설정 (왜 https://인지, anon key 가져오는 법)
       - 서비스 관리 스크립트 주요 함수

    5. **배운 점** (Lessons Learned)
       - launchd는 systemd와 다르다: 의존성 순서 없음 -> 헬스체크 패턴 필요
       - 절대 경로 필수: launchd는 ~ 확장 안 함
       - PATH 환경변수 필수: Homebrew 바이너리 찾으려면 명시적 PATH 필요
       - Vite preview의 allowedHosts: DNS 리바인딩 방어 vs 터널 접근
       - MX 레코드와 CNAME 레코드는 독립적: 터널 추가해도 이메일 안 깨짐
       - Supabase Studio 절대 노출 금지: 54323 포트는 인그레스에 포함하지 않음

    6. **흔한 실수** (Common Mistakes)
       - 자격증명 파일 경로에 ~ 사용 -> launchd에서 못 찾음
       - KeepAlive: true 없이 SuccessfulExit 키만 사용 -> 의도한 종료에도 재시작
       - plist에 PATH 없음 -> npm, cloudflared 못 찾음
       - Docker 시작 전 Supabase 시작 -> "Cannot connect to Docker daemon"
       - config.yml catch-all 규칙 누락 -> 터널 설정 검증 실패
       - allowedHosts 미설정 -> "Invalid Host header" 에러

    7. **테스트** (Testing/Verification)
       - 서비스 상태 확인 방법 (launchctl list, 스크립트 status)
       - HTTPS 인증서 확인 (curl -vI)
       - MX 레코드 확인 (dig MX)
       - 전체 유저 플로우 테스트 체크리스트
       - 로그 확인 방법 (/tmp/rollbook-*.log)

    8. **다음 단계** (Next Steps)

       - nginx 전환 고려 시점 (대규모 트래픽)
